## 1. 总体结论

核心链路质量良好：状态机、凭证主路径、MCP 桥接、确认字面量防伪机制与 `docs/mcp-bridge.md` 的设计一致，类型纪律克制（无真实 `any`/`@ts-ignore`），所有子进程调用均为参数数组、无 shell 拼接，全库无硬编码密钥。

**真正的缺口在网络边界**：daemon 以零鉴权监听所有网卡，使"确认字面量""人工审批门""凭证不出本机"等上层设计在网络层面全部失效——存在至少三条独立的未认证远程代码执行/凭证读取路径。这是外部 Pilot 的阻断项，必须在本文件 §6.1 的整改完成前避免把安装脚本分发给外部用户。

## 3. 安全发现

### 3.1 高危（4 条，全部复核确认）

共同特征：未认证 + 网络可达。只要第 1 条存在，其余各条都升级为远程可利用。

| # | 发现 | 出处 | 影响 |
| --- | --- | --- | --- |
| S1 | daemon 无鉴权监听所有网卡。`serve()` 未传 hostname，默认 `0.0.0.0`；`app.ts` 全文无 auth 中间件 | `apps/daemon/src/index.ts:45`、`apps/daemon/src/app.ts` | 同网段任意主机可读写凭证、触发部署与发布 |
| S2 | 未认证 RCE（自动更新）。`POST /api/update` 直接 `git pull` + `npm install` + `npm run build` | `apps/daemon/src/app.ts:257-279` | 任何可达 3737 端口者可植入恶意依赖/代码 |
| S3 | 仓库导入 URL 可执行任意命令。`importRepositoryUrl` 仅 `z.string().url()`（不限 scheme），原样传给 `git clone`；git 的 `ext::` 协议会执行 URL 中的命令 | `apps/daemon/src/app.ts:41`、`:608` | 未认证 RCE；`file://` 亦可读本地仓库 |

### 3.4 确认干净的方面

- 全库无硬编码 secret（`ghp_`/`sk-`/`AKIA`/私钥模式无命中）；`.gitignore` 覆盖 `.env`、`.agent-dev`、sqlite、`*.key`；`SECURITY.md` 无明显缺口。

## 6. 整改方案

按优先级分五批。每批内部可独立提交；P0 完成前不分发安装脚本给外部用户。

### 6.1 P0 网络边界（阻断项，Pilot 前必须完成）

1. ✅ **绑定回环（2026-08-31 完成）**：`apps/daemon/src/index.ts` 的 `serve()` 已加 `hostname: '127.0.0.1'`。实跑验证：`netstat` 仅 `127.0.0.1:3799` 监听、回环请求 200、局域网地址（192.168.31.69）请求被拒绝；daemon 22 项测试全绿。
2. **本机 token 鉴权**：daemon 启动时生成随机 token，写入仅当前用户可读的文件（如 `~/.agent-dev/daemon-token`，0600）；所有 `/api/*` 路由经一个中间件校验 `Authorization: Bearer <token>`；Studio 启动时读取该文件并在请求头携带；MCP 桥接同样携带。健康检查类只读路由可豁免，但豁免清单要显式。注意：S5（审批可伪造）在单机场景靠此缓解——非浏览器、非本机的请求首先进不来。
3. **URL scheme 白名单**：`importRepositoryUrl` 从 `z.string().url()` 收紧为仅 `https://`（或 `https://` + 显式 SSH 白名单），拒绝 `ext::`/`file://`/`javascript:` 等；PR 证据等所有最终渲染为链接的 URL 同样限制 `http(s)`（覆盖 S3、S7）。
4. **门控 `/api/update`**：Pilot 期间直接移除 `POST /api/update` 与 `GET /api/update/check`（Studio 的更新提示改由用户手动 `git pull`），或至少要求与鉴权相同的 token + 确认字面量；同时决策 secret-backend 的去留（见 6.3-1）。

### 6.2 P1 状态机与校验一致性

5. `advanceDelivery`：两张表的写入包进同一事务（SQLite 支持）；`send` 前后比较状态值，非法事件（状态未变）显式抛错而非静默吞掉（`packages/storage/src/index.ts:1555-1573`）。
6. `app.ts:819/850/863/876` 四条 runtime 路由补 zod schema（含 `agentId` 的类型与长度约束），与其余路由的确认字面量写法统一。
7. 顺带检查 `:456` 处唯一未 `await` 的 `persist()`。

### 6.3 P2 清理与一致性

8. **secret-backend 去留决策**（需用户拍板）：无消费者且是 S4 载体——默认建议移除整条链路（`packages/provider-cli/src/secret-backend/` + `app.ts:282-398` 的 9 条路由）；若保留，必须先完成 P0 鉴权并补测试与文档。
9. 删除根目录遗留的 `install.sh`（或合并进 `scripts/install-macos.sh`），消除双入口歧义。
10. 清理死代码：`buildCodexExecutionPlan`、`formatDoctorSummary`、`isPipelineBlocked` 等；`detectDrift` 保留（接口契约，四适配器已实现，后续会消费）。
11. 确认字面量收敛为单一导出常量，`app.ts`/`mcp.ts`/Studio 三处引用同一事实源。
12. 文档与版本对齐：`handoff.md:84` 的 7 步改 9 步；`/api/health` 版本号改为从 `apps/daemon/package.json` 读取（对齐 MCP 桥的做法）；决策是否升版本号为 `0.2.0`。

### 6.4 P3 Windows 兼容
