# Agent-Dev 产品愿景与宪法

> 状态：产品原则基线  
> 日期：2026-08-02

## 1. 产品愿景

随着 AI 大幅降低代码生产成本，产品交付的瓶颈正在转向技术选型、账号连接、环境变量、权限、CI、Preview、生产发布、验收和长期维护。

Agent-Dev 的目标不是生成更多代码，而是让 AI 生成的软件具备可信赖的交付能力：

> 用户负责产品目标、体验与关键取舍；Agent-Dev 负责把这些决定转化成可发布、可验证、可维护的工程系统。

## 2. 产品类别

Agent-Dev 属于 Agentic Product Delivery Platform，即 AI Agent 驱动的产品工程与交付控制平台。

它不是：

- Codex 或 Claude Code 的替代品；
- 仅生成源码的应用构建器；
- 仅提供模板的脚手架；
- 仅展示流水线的运维平台；
- 依靠聊天记录维持状态的 Agent 包装器。

Agent-Dev 管理的最小单位是产品生命周期，而不是一次任务、一个 PR 或一个仓库。

## 3. 责任边界

### 用户负责

- 产品服务谁、解决什么问题；
- 功能范围、体验、审美与业务优先级；
- 成本、隐私、数据和外部影响决策；
- Preview 体验验收；
- 生产发布与最终 Approval。

### Agent-Dev 负责

- 提供经过验证的产品 Blueprint 和默认规范；
- 把需求转成规格、验收标准和实施任务；
- 调用可替换的 Agent Runtime 实现、测试和修复代码；
- 编排 GitHub、Supabase、Cloudflare、Vercel 等平台；
- 执行确定性 Policy，限制 Agent 权限；
- 聚合真实 CI、部署、测试和人工验收证据；
- 识别漂移、过期配置和维护任务；
- 给出明确的交付状态和残余风险。

Agent-Dev 可以保证流程和证据完整，不能保证产品获得市场成功。

## 4. 产品宪法

### 4.1 默认优于选择

新手模式应替用户决定约 90% 的工程问题，只询问会改变产品、成本、隐私或风险的事项。候选项和自定义能力是逃生口，不是默认体验。

### 4.2 自动化程度通过信任获得

自治能力按项目和动作逐步提升：观察、计划、执行可逆操作、自动修复、Preview 发布、生产批准。不存在一个不区分风险的“全自动”开关。

### 4.3 AI 推理，Policy 授权

大模型可以提出方案，但不能通过 Prompt 获得生产权限。确定性 Policy、GitHub Rulesets、Environment Approval 和供应商权限是最终约束。

### 4.4 所有动作可见、可解释、可验证、可恢复

重要动作必须说明目标、原因、影响、成本、权限、验证方式和恢复方案。“AI 已处理”不构成完成证据。

### 4.5 外部事实高于 Agent 自述

交付状态以 GitHub Checks、Deployment Records、Preview URL、数据库状态、冒烟测试和人工验收为准，不以 Agent 的自然语言总结为准。

### 4.6 用户拥有产品

代码、仓库、数据、域名、云资源和 Blueprint 归用户所有。用户退出 Agent-Dev 后，产品仍可构建、部署和维护；模型和供应商均可替换。

### 4.7 项目记忆必须结构化

聊天是过程，不是事实源。Blueprint、Policy、ADR、Delivery Run、Evidence 和 Delivery Report 构成长期项目记忆。

### 4.8 规范是可版本化的当前决定

规范必须记录适用范围、来源、版本、选择原因、覆盖关系和迁移路径。更换数据库或部署供应商是一个受控迁移，不是立即生效的设置修改。

### 4.9 交付之后仍需维护

依赖过期、Secret 失效、CI 漂移、环境不一致、埋点中断和安全风险都属于产品生命周期的一部分。

### 4.10 开放标准，商业化执行

长期建议开放 Blueprint Schema、模块格式、Agent Runtime Adapter 和 Provider Adapter 接口；托管运行时、Secrets、团队治理、审计、自动修复和维护控制面可以商业化。

## 5. 产品模式

### 新手模式

- 按产品类型选择模板；
- 使用默认技术栈和 SOP；
- 不显示模型参数、YAML、Token 和流水线细节；
- 只在账号授权、费用、隐私、权限和生产发布时询问；
- 最终仍可切换到专业模式。

### 专业模式

- 导入现有仓库；
- 编辑 Blueprint、质量契约、环境和审批策略；
- 选择本地、托管或自定义 Agent Runtime；
- 查看 Dry Run、配置 Diff、审计和迁移计划；
- 创建和共享自定义模块。

两种模式必须共享同一个 Blueprint、Policy 和 Delivery State Machine，不能演变成两套产品。

## 6. 核心产品承诺

第一阶段：

> 在不接管用户产品所有权的前提下，把一次真实 Web 产品交付从大量人工协调压缩成少数产品决策和最终验收。

长期：

> 让任何合规的 AI Agent 都能依据同一套产品规范，在用户拥有的基础设施上持续、可审计地交付和维护软件。
